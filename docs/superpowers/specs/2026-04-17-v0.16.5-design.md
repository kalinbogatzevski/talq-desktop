# v0.16.5 Design — Emoji, Image Viewer, Welcome Changelog

Date: 2026-04-17
Status: approved, ready for planning
Author: Kalin (with Claude)

## Summary

Six interrelated changes in one release:

1. **Emoji data layer** — bundled Twemoji PNG assets + shortcode/short-form metadata, reused by everything below.
2. **Emoji picker widget** — Telegram-style: categories, search, recents, skin-tone variants.
3. **Composer integration** — `:)` / `:shortcode:` autoreplace on space, shortcode autocomplete as you type, 😀 picker button.
4. **ChatPainter Twemoji rendering** — message bodies and reaction pills render Twemoji pixmaps instead of system emoji font.
5. **Image viewer** — proper single-instance top-level window with Esc-to-close, pan, Ctrl-wheel zoom, +/- keys, fit/100% toggle.
6. **Welcome screen redesign** — split layout with existing server card on the left, scrollable changelog on the right, plus a home navigation path (clickable logo + 🏠 button) so the welcome is reachable from any active conversation.

Items are largely independent and can be implemented in parallel. Bundled installer grows by roughly 4 MB from the Twemoji assets.

## Section 1 — Emoji data layer

New module `src/core/EmojiData.{h,cpp}` — single source of truth for all emoji lookups.

### Bundled data
A JSON sourced from [`emoji-datasource-twitter`](https://github.com/iamcal/emoji-data) (pinned version) is compiled at build time into a `.cpp` containing a `static const QVector<EmojiEntry>`. Roughly 3600 entries.

Per-entry fields:
- `codepoints` — `QString`, the Unicode sequence that renders the emoji.
- `category` — enum: Smileys, People, Animals, Food, Activities, Travel, Objects, Symbols, Flags.
- `name` — canonical short name (e.g. `"grinning face"`).
- `shortcodes` — `QStringList`, one or more `:foo:` tokens (e.g. `:grinning:`).
- `shortForms` — `QStringList` of plain-text shortcuts (e.g. `[":)", ":-)"]`). Empty for most.
- `skinToneVariants` — optional list of codepoint sequences for skin-tone variations.
- `keywords` — for search.

### Twemoji PNG assets
- Twemoji v14 PNGs at 72×72, bundled under `resources/twemoji/72x72/<hex-codepoints>.png`, embedded via a Qt resource file (`resources/twemoji.qrc`) so the installed app ships a single binary that already contains them (no loose asset files, no disk layout constraints).
- Approximately 3.5–4 MB installed size.

### Runtime cache
```cpp
QHash<QString, QPixmap> m_pixmapCache; // key: codepoints + ":" + sizePx
```
Lazy-load on first use: open the resource, decode, scale to target size, store. No file I/O after first use per `(emoji, size)` combination.

### Public API
```cpp
const EmojiEntry *findByShortcode(const QString &sc);      // ":smile:"
const EmojiEntry *findByShortForm(const QString &sf);      // ":)"
QVector<const EmojiEntry*> search(const QString &query);   // ranked, name+keywords+shortcodes
QPixmap pixmapFor(const QString &codepoints, int sizePx);  // cached
QVector<const EmojiEntry*> allInCategory(Category c);
QVector<const EmojiEntry*> recent();                       // most recent first
void pushRecent(const EmojiEntry *e);                      // moves to front, trims to 24
```

### Persistence
- Recents: `QSettings` list of codepoint strings under key `emoji/recent`, max 24 entries.
- Preferred skin tone (if user ever picks one): `QSettings` key `emoji/skinTone`.

New `src/ui/EmojiPickerWidget.{h,cpp}` — single self-contained widget, roughly 400 lines.

### Layout (~400×360 px popup)

├─────────────────────────────────────────┤
│ 😀 👋 🐵 🍎 ⚽ ✈️ 💡 ❤️ 🇦                │ ← 9 category tabs
├─────────────────────────────────────────┤

│  … scrollable grid (9 per row) …        │
└─────────────────────────────────────────┘

### Rendering
- Each cell is a small `QAbstractButton` subclass that paints a `QPixmap` from `EmojiData::pixmapFor()`.
- Flat style, hover tint, pointing-hand cursor.
- 32 px icons on a 40 px cell.

### Interactions
- Clicking a category tab scrolls the grid to that category's section header.
- Typing in the search field filters the grid in place (hide/show cells), bypassing category headers.
- Enter in the search field selects the top hit.
- Long-press (300 ms) or right-click on an emoji that has skin-tone variants pops up a small row of the 6 tones above the cell; left-click on a tone selects it.
- Esc closes the popup.

### Signal
```cpp
void emojiSelected(const QString &codepoints, const QString &insertText);
```
`insertText` is typically the codepoints themselves, but for reactions it's the same value — consumer decides what to do with it.

### Where it's used
- Composer 😀 button opens it as a popup anchored above the button.
- `ChatPainter` right-click context menu: the existing 6-emoji row gets a 7th `…` cell that opens the picker.
- "More" button on the reaction pills (future — flag as phase 2 if scope creeps).

## Section 3 — Composer integration

Edits to `src/ui/ComposerWidget.{cpp,h}` — around 150 lines added.

### Short-form autoreplace
Triggered on `QTextEdit::textChanged`. On every change, inspect the text just before the cursor. If the two or three characters preceding a trailing space match a known short-form, replace the short-form with the emoji codepoint(s), preserving the trailing space.

Lookup uses `EmojiData::findByShortForm()`, which indexes every entry's `shortForms` field at startup into a `QHash<QString, const EmojiEntry*>`. The source data marks roughly 30 emojis with at least one short-form:
`:) :-) :D :-D :P :-P :( :-( ;) ;-) :o :-o :O :-O :| :-| :/ :\ <3 </3 :*` and variants.

### Shortcode autoreplace
Same trigger. Regex `:[a-z0-9_+-]+:` before the trailing space. Lookup via `EmojiData::findByShortcode()`. If hit, replace; otherwise leave the text alone.

### Undo
Each replacement is wrapped in `QTextCursor::beginEditBlock` / `endEditBlock` so Ctrl+Z restores the original `:)` / `:smile:` text in one step.

### Shortcode autocomplete
When the cursor sits inside a partial `:word` token (colon followed by word chars, no closing colon yet):
- Query `EmojiData::search(word)`.
- Show a small `QListView` popup anchored above the composer with the top 6 matches rendered as "emoji — :shortcode:".
- Up/Down arrows move selection; Enter or Tab picks and replaces the typed `:word` with the chosen emoji + space; Esc dismisses.

### Picker button
A flat 😀 icon button left of Send. Clicking opens `EmojiPickerWidget` as a popup. `emojiSelected` signal inserts the codepoints at the cursor position.

### Caption bar
Reuses the same composer, so no extra changes.

## Section 4 — ChatPainter Twemoji rendering

Edits to `src/painter/ChatPainter.cpp`, `src/painter/LayoutEngine.cpp`, `src/painter/MessageLayout.h`, and the reaction pill renderer — roughly 200 lines of changes, zero new files.

### Problem
`QPainter::drawText` renders emoji through the system font (Segoe UI Emoji on Windows). We want Twemoji pixmaps everywhere.

### Approach: layout-time pre-pass
1. In `LayoutEngine::computeLayout`, after the HTML → `QTextDocument` step, walk the plain text to find emoji runs. Detection: `QChar::category()` plus the Unicode Extended_Pictographic property, grouped into grapheme clusters via `QTextBoundaryFinder::Grapheme` so ZWJ sequences and skin-tone modifiers stay together.
2. For each emoji run, record `{ docPosition, codepoints, visualWidthPx }` in a new `QVector<EmojiRun> emojiRuns` on `MessageLayout`.
3. Replace the emoji characters in the `QTextDocument` with a single space whose advance width equals `visualWidthPx`, so Qt's text layout leaves exactly the right gap but draws nothing for those positions.
4. At paint time, for each `EmojiRun`: compute the (x, y) screen position via `QTextLayout::cursorToX`, fetch `QPixmap` from `EmojiData::pixmapFor(codepoints, lineHeight)`, `drawPixmap` at that position.

Consequences:
- Word wrapping, selection, and hit-testing stay correct because the document owns the width.
- Selection highlight covers emoji positions naturally.
- Copy-to-clipboard must re-substitute the original codepoints at copy time using the `emojiRuns` table — handled in `ChatPainter::copySelectedText` and in the selection-mode bulk copy path.

### Reaction pills
`ChatPainter.cpp` around line 1393: swap the `drawText(emoji)` for `drawPixmap` at a fixed 18 px target. The pill width math already uses `horizontalAdvance`, which continues to work because the pill width is computed from the pixmap size.

### Shared helper
```cpp
void ChatPainter::drawEmoji(QPainter *p, const QString &codepoints,
                            const QPointF &pos, int sizePx);
```
Called by the body-text paint path and by the reaction renderer.

### Font fallback
If `EmojiData::pixmapFor()` returns a null pixmap (codepoint not in our bundled set — would only happen for emoji added after our data version), fall back to `drawText` in Segoe UI Emoji. Log the missing codepoint once.

### Performance
Pixmap cache is keyed by `(codepoints, sizePx)`. A typical chat session sees maybe 20 unique emojis; the cache stays tiny. First paint of a new emoji costs one PNG decode (well under 1 ms) plus a scale.

## Section 5 — Image viewer

New `src/ui/ImageViewerDialog.{h,cpp}` — standalone top-level window, roughly 180 lines. Replaces the inline `QDialog` currently created at `MainWindow.cpp:838`.

### Window
- `Qt::Window` flag — proper taskbar entry, own Alt+Tab slot.
- Black background.
- Frameless title strip overlay showing filename + close ✕; fades in on mouse movement, fades out after 2 seconds of idle.
- Initial size: 80% of screen, centered. Last geometry is remembered in `QSettings`.

### Single-instance
`MainWindow` holds `QPointer<ImageViewerDialog> m_imageViewer`. On `fileClicked` for an image:
- If `m_imageViewer` is null, create it.
- Otherwise call `setImage(fileId, fileName)` on the existing instance, then `raise()` and `activateWindow()`.
Never spawn a second viewer.

### Viewport
`QGraphicsView` + `QGraphicsScene` + `QGraphicsPixmapItem` — gives pan and zoom for free.

- Fit-to-window on load (scale so the pixmap fits; call this scale 1.0 for user-facing zoom purposes).
- Pan: `setDragMode(QGraphicsView::ScrollHandDrag)`. Click-drag moves the image. Cursor becomes open hand / closed hand.
- Zoom:
  - **Ctrl + wheel** → zoom toward the cursor, 1.15× per notch, clamped between 0.1× and 8×.
  - **+ / -** keys → zoom at view center with the same step.
  - **0** → reset to fit-to-window.
  - **1** → 100% (one image pixel per screen pixel).
  - **Double-click** → toggle between fit and 100%.
- `setRenderHint(QPainter::SmoothPixmapTransform)` for clean scaling.
- Wheel without Ctrl → pan vertically (default `QGraphicsView` behavior), useful when zoomed beyond fit.

### Keys
- `Esc` → close. Override `keyPressEvent` explicitly — do not rely on `QDialog::reject()` since the window is not a modal dialog.
- `←` / `→` → prev/next image in the same conversation. Optional; flag as phase 2 if it causes scope creep.

### Full-resolution image
Currently `MainWindow` passes `m_chatPainter->cachedPreview(fileId)` which is the thumbnail. For the viewer we want the full image.

- Add `ApiClient::fetchFileImage(fileId, callback)` — GET on `/remote.php/dav/files/…` for images up to 20 MB (larger → refuse with a message in the title strip).
- Show the cached preview immediately while the full-res downloads (progress indicator in the title strip), then swap in the full image when it arrives.

A `QSplitter` (horizontal) inside `m_welcomeWidget`:
- Left: existing server card wrapped in its own `QWidget`, content preserved verbatim, moved into a sub-widget.
- Right: `QTextBrowser` with Markdown-rendered changelog.
- Stretch factors: server card 0 (fixed 420 px), changelog 1.
- At window widths below 1100 px, collapse to a single column (server card on top, changelog below) via a `resizeEvent` hook.

### Changelog source
- `CHANGELOG.md` is embedded at build time via a new Qt resource (`resources/changelog.qrc`) so the in-app view updates automatically on every rebuild.
- `QTextBrowser::setMarkdown(QString::fromUtf8(resource))`. Qt 6 renders H2/H3/bullets with sane defaults.
- Minimal CSS via `setStyleSheet` for the dark theme: muted header color, off-white body, teal links, slightly larger H2 for version numbers.
- No images, no JavaScript.

### Home navigation
Two entry points, both emitting a new `SidebarPainter::homeRequested()` signal:

1. **Clickable logo/title in the sidebar header** — the existing painted "TalQ" title gets a hit region; clicking it emits `homeRequested`.
2. **🏠 icon button** — a flat 28×28 button next to the search box in the sidebar header. Tooltip "Home".

`MainWindow` connects `homeRequested` to:
- Clear active conversation in `m_messages`.
- `m_sidebar->setSelectedIndex(-1)`.
- Close any open thread panel.
- `m_chatPainter->hide()`.
- `m_welcomeWidget->show()`.
Reverse of `onConversationSelected`.

Search box behavior is unchanged. Typing in search on the welcome screen filters the sidebar as usual; clicking a result loads that conversation, which implicitly leaves the welcome screen.
