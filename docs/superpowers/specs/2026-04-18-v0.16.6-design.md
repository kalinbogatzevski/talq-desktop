# v0.16.6 Design — Sidebar Twemoji + Image Viewer Clipboard/Save

Date: 2026-04-18
Status: approved, ready for planning
Author: Kalin (with Claude)

## Summary

Two small additive wins after v0.16.5 ships:

1. **Twemoji in sidebar and thread previews** — the conversation list's last-message preview currently uses the system emoji font. Apply the same overlay-render pattern used in `ChatPainter::paintMessageEmojis` so the sidebar matches chat visuals.
2. **Image viewer clipboard and save** — add Ctrl+C, Ctrl+S, and a "⋯" overlay menu to `ImageViewerDialog` so the user can copy or save the displayed image.

No new dependencies, no installer size change, no behavior changes to existing flows. Estimated ~200 lines total.

## Section 1 — Twemoji in sidebar / thread previews

### Problem
v0.16.5 gave chat bodies and reaction pills Twemoji via `ChatPainter::paintMessageEmojis`. The sidebar's conversation list (`src/painter/SidebarPainter.cpp`, around line 460) and the thread list (`src/painter/ThreadsPainter.cpp`) still call `QPainter::drawText` with the preview string, so they render emoji in Segoe UI Emoji. Users see two styles in one screen.

### Approach

Introduce a shared helper, `EmojiTextRenderer`, that draws a short string with Twemoji substitution. It reuses the same primitives as `ChatPainter::drawEmoji` but is packaged for re-use on simple text strings that don't need full `QTextDocument` layout.

New file `src/painter/EmojiTextRenderer.{h,cpp}` — a tiny namespace:

```cpp
namespace EmojiTextRenderer {

// Draws `text` starting at `origin.topLeft()`, clipped to `origin`, eliding if needed.
// Emoji clusters are rendered via Twemoji pixmaps; non-emoji chars via QPainter::drawText
// using the painter's current font. Returns the right edge of the drawn text (for chaining).
qreal drawElided(QPainter *p, const QRectF &origin, const QString &text,
                 Qt::TextElideMode elide = Qt::ElideRight);

} // namespace EmojiTextRenderer
```

Implementation:
1. Walk `text` with `QTextBoundaryFinder::Grapheme`, producing runs typed as `{ kind: Text|Emoji, start, end }`.
2. Compute each run's pixel width: `fm.horizontalAdvance(run.text)` for text; `lineHeight * 1.1` (or the measured system advance) for emoji.
3. If total width exceeds `origin.width()`, elide from the end: repeatedly drop the last run (or trim the last text run char-by-char) and append the `…` ellipsis until it fits.
4. Draw: for each run, either `drawText` at the current x or fetch `EmojiData::pixmapFor(cluster, lineHeight)` and `drawPixmap`. Advance x by the run width after each.
5. Return the final x for chaining with badges/timestamps.

### Call sites

- `SidebarPainter.cpp` around line 460 — replace `p->drawText(... elidedPreview)` with a call to `EmojiTextRenderer::drawElided`.
- `ThreadsPainter.cpp` — same call site for thread preview line (if it renders a preview string).
- (Optional, follow-up) conversation display names that include emoji — skipped this release unless the change is trivial.

### Performance

The renderer is called per visible conversation row. A typical sidebar shows ~15 rows. Emoji lookup hits the existing `EmojiData` pixmap cache, so repeated emojis across rows cost one PNG decode total. No measurable overhead.

### Fallback

If an emoji cluster has no Twemoji PNG (lookup returns null), the renderer falls back to `drawText` for that cluster — identical to the previous behavior for that one emoji. No runtime breakage.

## Section 2 — Image viewer clipboard and save

### Problem
`ImageViewerDialog` (added in v0.16.5) displays images but gives no way to copy them elsewhere or save a local file. Everyday workflows need both.

### Approach

All changes live in `src/ui/ImageViewerDialog.{h,cpp}`:

1. **Hold the currently displayed full-res image** — already tracked implicitly in the `QGraphicsPixmapItem`, but add an explicit `QImage m_currentImage` member so we don't have to convert back from the pixmap item each time.

2. **Ctrl+C handler** — extend `keyPressEvent`:
   ```cpp
   case Qt::Key_C:
       if (event->modifiers() & Qt::ControlModifier) {
           if (!m_currentImage.isNull())
               QApplication::clipboard()->setImage(m_currentImage);
           return;
       }
       break;
   ```

3. **Ctrl+S handler** — similarly:
   ```cpp
   case Qt::Key_S:
       if (event->modifiers() & Qt::ControlModifier) { saveAs(); return; }
       break;
   ```
   `saveAs()` opens `QFileDialog::getSaveFileName`, defaulting to the current filename from the title bar, filter `*.png *.jpg *.jpeg *.bmp`, and writes via `QImage::save`. On error, overlay error text in the title bar for 3 seconds (reuse title bar area — no new UI).

4. **"⋯" overlay button** — small flat button in the title strip next to the filename. Clicking it pops up a small menu: "Copy image (Ctrl+C)" / "Save as… (Ctrl+S)". This is the discoverability layer for keyboard-averse users.

5. **Update `applyPixmap`** to cache `m_currentImage`:
   ```cpp
   void applyPixmap(const QImage &img) {
       m_currentImage = img;
       // …existing body unchanged…
   }
   ```

### UX

- Ctrl+C and Ctrl+S work whether the viewer shows the full-res (once loaded) or the thumbnail placeholder (before full-res arrives). When still showing the thumbnail, copying/saving uses that thumbnail — acceptable and noted by the small badge "preview" in the title strip if the full-res hasn't loaded yet (stretch feature, can drop if overscoped).
- Save defaults to PNG; user can pick JPEG via the filter.
- No progress bar for save — `QImage::save` is synchronous and fast for typical sizes.
