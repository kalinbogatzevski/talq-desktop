# v0.17.0 Design — Compose-side @mentions

Date: 2026-04-18
Status: approved, ready for planning
Author: Kalin (with Claude)

## Summary

TalQ already **receives** mentions correctly — `Message::fromJson` at `src/models/Message.cpp:30-33` renders `messageParameters` of type `user`/`call`/`guest` as styled teal pills, and the sidebar shows a mention-color badge for unread mentions. What is missing is **composing** mentions: typing `@bob` currently sends plain text, so the server does not flag Bob and he gets no notification.

This spec adds compose-side mentions modeled on the `:shortcode:` autocomplete already shipped in v0.16.5. Typing `@` at a word boundary opens an autocomplete popup driven by the server's `/apps/spreed/api/v4/chat/{token}/mentions` endpoint. Picking a row inserts `@userid` (or `@"user id"` when the id contains special characters) into the composer as plain text. On send, the server parses the mention marker and echoes the enriched message back to all clients, which render it as the existing teal pill.

## Decisions

- **Scope:** user mentions plus `@all`. No `@here` (not a NC Talk concept).
- **Compose UX:** raw `@userid` plain text in the composer, no chip/pill in the editor. Editable like any other text.
- **Fetching:** on-demand per keystroke, debounced 150 ms. No prefetch.
- **Empty partial (`@` alone, followed by a space or cursor):** show the top participants returned by the server for `search=""`, plus `@all` at the top.

## Section 1 — Mentions API

### New small header `src/core/MentionCandidate.h`

```cpp
#pragma once

#include <QString>

struct MentionCandidate {
    QString id;          // e.g. "alice", "all"
    QString label;       // display name, e.g. "Alice Smith"
    QString source;      // "users" | "groups" | "calls" | "guests"
};
```

### `ApiClient` additions

```cpp
// ApiClient.h
void fetchMentions(const QString &token,
                   const QString &search,
                   std::function<void(const QVector<MentionCandidate> &)> cb);
```

Implementation:

- Endpoint: `GET /ocs/v2.php/apps/spreed/api/v4/chat/{token}/mentions?search=<query>&limit=20`.
- Auth: follow the existing inline basic-auth pattern used by `fetchFileImage` (set `Authorization` header from `m_user`/`m_password` as base64).
- Headers: `OCS-APIRequest: true`.
- On response: parse `ocs.data[]` into `QVector<MentionCandidate>`. Each row has `id` (string), `label` (string), `source` (string). The server includes a synthetic `{id:"all", label:"Everyone", source:"calls"}` entry when appropriate; we don't need to inject one client-side.
- On HTTP error (4xx/5xx) or network failure: call the callback with an empty vector. Log once at qWarning level for 403/404 so an auth/permission bug is visible in the debug log.

### No caching
The composer's popup debounces keystrokes; the API layer makes one call per fire. Typical rooms are small and fetches are fast on LAN. No cache layer.

## Section 2 — Composer `@`-trigger and popup

All changes land in `src/ui/ComposerWidget.{h,cpp}`, mirroring the existing `:shortcode:` autocomplete.

### New members

```cpp
QListWidget *m_mentionPopup = nullptr;   // lazily created
QTimer      *m_mentionDebounce = nullptr;
QString      m_pendingMentionQuery;       // latest query we armed the debounce for
int          m_mentionWordStart = -1;     // position of the '@' in the composer text
```

### Trigger detection (new slot `maybeShowMentionCompletion`)

Connected to `m_input->textChanged`. Called on every keystroke. Logic:

1. Get the text and cursor position.
2. Walk backward from `cursor - 1`: accept chars in `[A-Za-z0-9._@+-]`. Stop at the first `@` (record its position as `m_mentionWordStart`) or bail if we reach a non-matching char first.
3. If we found an `@`, check the char immediately before it. If it's not start-of-text and not whitespace/newline, abort — this is an email fragment, not a mention.
4. Extract `partial = text.mid(mentionWordStart + 1, cursor - mentionWordStart - 1)`. `partial` can be empty (user just typed `@`).
5. If the shortcode autocomplete popup is currently visible, hide the mention popup and bail. Mention popup cannot coexist with shortcode popup.
6. Otherwise arm the 150 ms debounce with `partial` as the query. If the debounce is already armed for a different query, reset it.

### Debounce timer

Single-shot `QTimer`. On fire:

- Capture the current partial (may have changed since arming).
- Call `m_api->fetchMentions(m_token, partial, ...)`.
- In the callback:
  - If the cursor has moved before `m_mentionWordStart` or a non-`@word` char appeared in between, discard the result (the user stopped typing a mention).
  - Otherwise populate the popup (see below) and show it.

### Popup

Lazily created on first use:

- `QListWidget` with `Qt::Popup` window flag anchored to the `ComposerWidget`.
- Stylesheet matching the existing shortcode popup (dark background, rounded corners, selected-row accent).
- Parented to `this->window()` so it floats above the chat.
- Positioned so its bottom edge is a few pixels above the composer's `m_input` (same math as `applyCompletion`'s popup placement).

Each row:

- **Avatar**: 24×24 pixmap. Use `AvatarProvider::fetchAvatar(userId, size, callback)` (already exists and is used by `ChatPainter`). Rows for `source == "calls"` (i.e. `@all`) use a static megaphone icon instead of an avatar.
- **Text**: bold display name on the first line, dimmed `@userid` on the second line. (`@all` shows "Everyone" / "Notify everyone".)
- Row height: ~40 px to fit the avatar and two text lines.

Visible rows cap at 6 (the server's `limit=20` gives headroom; scrolling past 6 is rare).

### Keyboard handling

Extend the existing `eventFilter` on `m_input`. The filter currently handles the shortcode popup; add a parallel branch for the mention popup. Behavior when mention popup is visible:

- `Up`: select previous row (clamped to 0).
- `Down`: select next row (clamped to `count - 1`).
- `Enter` / `Return` / `Tab`: call `applyMentionCompletion(currentRow())`.
- `Escape`: hide the popup.
- Any other key falls through to the text edit.

### `applyMentionCompletion(row)`

- Fetch the `MentionCandidate` from the picked row's user-data.
- Compute the replacement string:
  - If `candidate.id == "all"`: `@all `.
  - Else if `candidate.id` matches `^[A-Za-z0-9._-]+$`: `@<id> `.
  - Else: `@"<id>" ` (quoted form for ids with spaces/punctuation).
- Replace the span from `m_mentionWordStart` through the current cursor position with the replacement, wrapped in a `QTextCursor::beginEditBlock` / `endEditBlock` so Ctrl+Z undoes the insert as one step.
- Hide the popup, reset `m_mentionWordStart = -1`.

## Section 3 — Send path (no code changes)

The existing `MessageListModel::sendMessage(text, replyId)` flow is unchanged. The server's `spreed` app parses `@userid` and `@"user id"` and `@all` tokens in the incoming message text, stores matching `messageParameters`, and echoes the enriched JSON back. All TalQ clients (including the sender's) already render that JSON via `Message::fromJson`, which turns the parameters into styled teal pills. No client-side post-processing is needed.

Recipient notification is triggered by the server based on the mentions it detected.

## Verification (manual)

Covered by smoke tests, not an automated suite (TalQ has no test framework beyond `tests/call_test.cpp`):

- In a shared group chat, compose `@bo` + pick `bogatzevski` → the popup shows the row with avatar, pick inserts `@bogatzevski ` at the cursor, send. Recipient gets a notification; the message in both clients shows the teal pill.
- In the same room, compose `@all` → single row, pick inserts `@all ` → send → all members get a notification.
- Edge: user id with period (`first.last`) — renders unquoted. User id with space — quoted form on insert.
- Edge: type `foo@bar.com` — no popup triggers (email fragment).
- Edge: offline / auth failure on the mentions endpoint — popup stays hidden, debug log has one warning.
