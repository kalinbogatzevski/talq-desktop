# v0.17.3 Design — Unread Divider

Date: 2026-04-18
Status: approved, ready for planning
Author: Kalin (with Claude)

## Summary

When you reopen a conversation that has new messages, TalQ currently shows them inline without any visual separator between already-seen and new. NC Talk web draws a "New messages" divider line across the chat at the last-read boundary, which makes it easy to jump straight to the first unread. We add that behavior, plus a subtle teal-tinted background below the divider to reinforce the "this block is new" visual.

The per-user last-read value is already tracked by `ConversationListModel` (`Conversation::lastReadMessage`, server-sourced). The only new state is a snapshot captured **before** `markAsRead()` fires on conversation-open, so the divider doesn't jump to the latest message the moment you open the chat.

## Data capture

### New state in `MessageListModel`

```cpp
// MessageListModel.h — private
int m_unreadBoundary = 0;
ConversationListModel *m_conversations = nullptr;

// public
int unreadBoundary() const { return m_unreadBoundary; }
void setConversationListModel(ConversationListModel *c) { m_conversations = c; }

// signals
void unreadBoundaryChanged();
```

### Capture in `setConversationToken`

In `MessageListModel::setConversationToken(const QString &token)`, **before** the existing `markAsRead()` / poller-restart flow:

```cpp
int newBoundary = (m_conversations && !token.isEmpty())
    ? m_conversations->lastReadMessageForToken(token)
    : 0;
if (newBoundary != m_unreadBoundary) {
    m_unreadBoundary = newBoundary;
    emit unreadBoundaryChanged();
}
```

Rationale for doing it here: `setConversationToken` is already the single entry point for conversation switches (home nav passes empty token; selecting a conversation passes a non-empty one). Capturing here naturally resets to 0 on home nav and snapshots the server's stored lastRead on open.

### Wire in `MainWindow`

One line, during initial wire-up alongside the other model connections:

```cpp
m_messages->setConversationListModel(m_conversations);
```

## Layout

### `MessageLayout` additions

```cpp
// MessageLayout.h — inside struct
bool showUnreadSep = false;
QRectF unreadSepRect;   // horizontal strip where the "New messages" pill sits
```

### Marking the separator row in `ChatPainter::rebuildLayouts`

`ChatPainter::rebuildLayouts` already loops over messages calling `LayoutEngine::computeLayout` per row. Do the "first unread" pass there:

1. Before the loop, pre-compute `firstUnreadIdx` — the lowest model index whose `id > m_unreadBoundary`. If nothing matches (caught up) or `m_unreadBoundary == 0` and no messages exist, `firstUnreadIdx = -1`.
2. Inside the loop, after `MessageLayout ml = LayoutEngine::computeLayout(...)` returns, if `i == firstUnreadIdx`:
   - Set `ml.showUnreadSep = true`.
   - Reserve a fixed-height strip by shifting the layout: `ml.unreadSepRect = QRectF(margin, ml.totalY, width - 2*margin, PainterTheme::unreadSepHeight);` then add `PainterTheme::unreadSepHeight` to every Y coordinate in `ml` that was computed relative to `startY` — in practice a small helper `ml.shiftBy(PainterTheme::unreadSepHeight)` added to `MessageLayout` that increments `totalY`, `totalHeight`, `bodyRect.top`, `avatarRect.top`, etc.
3. Propagate the shift to the running `y` cursor so the next layout starts below.

This keeps `LayoutEngine::computeLayout` unchanged (no signature churn) — the separator is purely a post-hoc decoration applied in `ChatPainter`.

`PainterTheme::unreadSepHeight = 28` — matches existing `dateSepHeight` for visual consistency.

## Rendering

### Divider pill in `ChatPainter`

New helper matching the shape of the existing `paintDateSep`:

```cpp
void ChatPainter::paintUnreadSep(QPainter *p, const MessageLayout &ml, qreal offsetY);
```

Drawn the same way as the date separator:
- Short centered pill with a 1-px teal accent line extending across the full width beneath it.
- Text: `"New messages"` (localizable via `tr()`), muted color, pill-style background using `PainterTheme::bgSurface`.
- Height: 28 px (matches existing date-sep height; configurable via `PainterTheme::unreadSepHeight`).
- Visually distinct from `paintDateSep` (which uses textSecondary on bgSurface): use `m_theme.accent` (teal) for the divider line + `m_theme.accent` for the pill text, so the teal tint below reads as a continuation.

Call site in `ChatPainter::paintEvent`: inside the main message paint loop, if `ml.showUnreadSep`, call `paintUnreadSep(p, ml, offsetY)` before `paintOwnMessage` / `paintOtherMessage`.

### Tinted background below the divider

In `ChatPainter::paintEvent`, **before** drawing messages (right after the canvas background fill):

```cpp
// Find the unread separator Y in canvas coords, if any.
qreal unreadY = -1;
for (const auto &ml : m_layouts) {
    if (ml.showUnreadSep) {
        unreadY = ml.unreadSepRect.top();
        break;
    }
}
if (unreadY >= 0) {
    // Fill from the divider's Y down to the bottom of the content area with a
    // very low-opacity accent tint. Only covers the visible viewport strip.
    qreal top = qMax(qreal(0), unreadY - m_scrollY);
    p.fillRect(QRectF(0, top, width(), height() - top),
               QColor(46, 196, 182, 10));  // ~4% opacity teal
}
```

Opacity is deliberately low (≈4%) so the tint registers subconsciously without fighting message content. Works on both dark and light themes since it's a tint, not an opaque block.

### Connect the signal in `ChatPainter`

Member `int m_unreadBoundary = 0;` plus slot `void setUnreadBoundary(int id)` that stores the value and calls `rebuildLayouts()` + `update()`. Connect in `setMessageModel`:

```cpp
connect(m_model, &MessageListModel::unreadBoundaryChanged, this, [this]() {
    setUnreadBoundary(m_model->unreadBoundary());
});
setUnreadBoundary(m_model->unreadBoundary());  // initial pull
```

## Behavior rules

| Situation | Result |
|---|---|
| Never opened this conversation (boundary=0) | All loaded messages are "unread" → divider above the oldest. |
| Boundary is set and messages exist above and below | Divider above the first message with `id > boundary`. |
| All messages have `id <= boundary` (caught up) | No divider drawn. |
| User switches to another conversation and back | New boundary captured from the per-token lastReadMessage (which was advanced by the previous visit's `markAsRead`), so the divider is at the new "frontier" or absent. |
| User scrolls up to load older history | Boundary is anchored by message id, not layout index — divider stays at the same messageId. Older messages render above it as they arrive. |
| Home navigation (empty token) | Boundary reset to 0. |

**The divider is frozen for the session** — no "clear after scroll past" logic. When you leave the conversation, `markAsRead` on the server catches up; the next time you open, the boundary is at (or past) where the old divider was. Matches Telegram/NC Talk web.

## Edge cases

- **New messages arrive while you're viewing**: they come in below the current content. Their `id > m_unreadBoundary`, so if the divider is already present they'll sit below it (good). If the conversation was caught up (no divider) when new messages arrive, should the divider appear? Per NC Talk convention: **no** — while the conversation has focus, incoming messages are considered read in-context, so no divider. Our behavior matches this naturally because `markAsRead()` is called on poll-result processing, advancing the server-side `lastReadMessage` for the current session; the boundary snapshot is only taken on conversation-switch, so in-focus arrivals never create a divider.
- **User switches conversation without sending anything**: `markAsRead()` was already called on open, so the server-side lastRead is at the newest visible message. Coming back next time, boundary is at the newest → no divider (until new messages arrive).
- **Incomplete history (poll lost some messages, history only partially loaded)**: the divider sits above the oldest loaded message whose id exceeds the boundary. If the boundary is between two loaded messages, the divider appears at the right spot. If the boundary is below all loaded messages (unusual — boundary less than oldest loaded id), the divider appears at the top of the loaded history, which visually means "everything you see might be new" — acceptable fallback.

## Verification (manual)

- Open TalQ, log in, pick a conversation you have unread messages in → "New messages" pill appears above the first unread; background below the pill has a subtle teal tint.
- Scroll up past the divider → it stays in place (anchored to the message id).
- Send a message → it goes below the divider; divider remains.
- Switch to another conversation and back → divider is either gone (if caught up) or at a new higher position.
- Open a conversation that's fully read → no divider, no tint.
- Open a conversation you've never opened before → divider above the oldest loaded message; tint covers everything.
- Switch to home (no active conv) → welcome screen shows, no divider anywhere.
