# v0.17.4 Patch Design — Divider auto-clear + edit-unwrap fix

Date: 2026-04-18
Status: approved, ready for planning
Author: Kalin (with Claude)

## Summary

Patch release addressing two user-reported issues from v0.17.3 / v0.17.2 testing:

1. **Unread divider doesn't clear after reading** — per-user feedback: "I read the message but the divider stays there." Add Discord-style auto-clear 2 s after the divider has scrolled above the viewport.
2. **Edited messages don't update in-place** — user reported: "I edited a message but my bubble didn't change; had to switch conversations and come back to see the edit." Root cause: the v0.17.2 `MessageListModel::editMessage` callback double-unwraps the OCS envelope. `ApiClient::handleReply` already hands callers `ocs.data` directly; my code calls `.value("ocs").value("data")` on top of that, yielding an empty object. `Message::fromJson({})` replaces the real bubble with a blank id=0 row that renders as empty.

Both are small, focused fixes. Shipping together as v0.17.4 because they're both post-v0.17.3 testing feedback and share no other dependency — one release is cleaner than two.

## Section 1 — Unread divider auto-clear

### State

Add to `ChatPainter.h`:

```cpp
// private members
bool   m_unreadSepDismissed = false;
QTimer *m_unreadSepDismissTimer = nullptr;   // single-shot 2s
```

### Trigger on scroll

In `ChatPainter::setScrollY` (already emits `scrollYChanged`; grep there), after the clamp/emit:

```cpp
// If the unread separator has scrolled above the viewport top,
// arm a 2-second dismissal timer. If the user scrolls back such that
// the separator re-enters the viewport, cancel the timer.
qreal sepBottom = -1;
for (const auto &ml : m_layouts) {
    if (ml.showUnreadSep) {
        sepBottom = ml.unreadSepRect.bottom();
        break;
    }
}
if (sepBottom > 0 && !m_unreadSepDismissed) {
    bool aboveViewport = sepBottom < m_scrollY;
    if (aboveViewport && !m_unreadSepDismissTimer->isActive()) {
        m_unreadSepDismissTimer->start();
    } else if (!aboveViewport && m_unreadSepDismissTimer->isActive()) {
        m_unreadSepDismissTimer->stop();
    }
}
```

Construct the timer in `ChatPainter`'s constructor:

```cpp
m_unreadSepDismissTimer = new QTimer(this);
m_unreadSepDismissTimer->setSingleShot(true);
m_unreadSepDismissTimer->setInterval(2000);
connect(m_unreadSepDismissTimer, &QTimer::timeout, this, [this]() {
    m_unreadSepDismissed = true;
    rebuildAllLayouts();   // un-reserve the strip
});
```

### Reset on conversation switch

In `ChatPainter::setUnreadBoundary` (added in v0.17.3), when the boundary changes, reset the dismissed state:

```cpp
void ChatPainter::setUnreadBoundary(int id)
{
    if (m_unreadBoundary == id) return;
    m_unreadBoundary = id;
    m_unreadSepDismissed = false;
    if (m_unreadSepDismissTimer) m_unreadSepDismissTimer->stop();
    rebuildAllLayouts();
}
```

### Paint + layout guard

In `ChatPainter::rebuildAllLayouts` where `firstUnreadLayoutIdx` is computed, add an early guard:

```cpp
int firstUnreadLayoutIdx = -1;
if (!m_unreadSepDismissed) {
    for (int i = 0; i < count; ++i) {
        int modelRow = count - 1 - i;
        int id = m_model->data(m_model->index(modelRow),
                               MessageListModel::IdRole).toInt();
        if (id > m_unreadBoundary) { firstUnreadLayoutIdx = i; break; }
    }
}
```

Existing tint overlay in `paintEvent` and `paintUnreadSep` are already gated on `ml.showUnreadSep` / `ml.unreadSepRect.isEmpty()`, so they drop naturally once the dismissed rebuild clears those fields.

### Behavior

- Open a conversation with unreads → divider + tint visible.
- User scrolls down (divider goes above viewport) → 2-s timer starts.
- If user scrolls back up within 2 s → timer stops, divider stays.
- Otherwise after 2 s → `rebuildAllLayouts` runs with `firstUnreadLayoutIdx = -1`, divider and tint vanish.
- Switch to another conversation and back → `m_unreadSepDismissed = false`; fresh boundary snapshot; divider may or may not appear depending on new boundary.

Footprint: ~25 LOC in `ChatPainter.{h,cpp}`.

## Section 2 — Edit-message unwrap fix

### Bug

`MessageListModel.cpp:839-840` (and the error branch at 831-833):

```cpp
QJsonObject updated = data.value("ocs").toObject()
                          .value("data").toObject();
```

`data` here is the callback's second argument from `ApiClient::put`, which routes through `handleReply`. `handleReply` at `ApiClient.cpp:90` already calls `callback(true, ocs["data"].toObject(), ocsStatus)` — passing the already-unwrapped payload. So my `.value("ocs").value("data")` double-unwrap returns an empty object, `Message::fromJson({})` yields a blank message with id=0, and I overwrite the real row with it.

### Fix

In the success branch: use `data` directly.

```cpp
if (!ok) {
    emit errorOccurred(QStringLiteral("Failed to edit message (HTTP %1)").arg(status));
    return;
}
for (int i = 0; i < m_messages.size(); ++i) {
    if (m_messages[i].id == messageId) {
        m_messages[i] = Message::fromJson(data);
        QModelIndex mi = index(i);
        emit dataChanged(mi, mi);
        break;
    }
}
```

In the error branch: `handleReply` strips OCS meta before our callback runs, so the server's error message isn't available at this layer. Drop the attempt to read `ocs.meta.message` and fall back to HTTP status. Future-work: widen `ApiClient::Callback` to also pass back meta error text — out of scope for this patch.

### Verification

Manual: compose a message, edit it, hit Enter. The bubble should update immediately with the new text + `(edited)` marker. No need to switch conversations.

Footprint: ~10 LOC modified in `MessageListModel.cpp`.
