# v0.18.0 Design — Presence, Search, Silent Send, Time-on-Hover

Date: 2026-04-18
Status: approved, ready for planning
Author: Kalin (with Claude)

## Summary

A four-feature bundle closing four of the most-requested Nextcloud Talk parity gaps in TalQ:

1. **Presence enhancement** — surface the status message + icon (e.g. "🎯 in a meeting"), add its own 60-second poll timer, show a subtitle line under the chat header, and make sidebar dot colors reflect away/DND/offline states too.
2. **Message search** — search within the currently active conversation via the Talk unified-search endpoint, with a results dropdown and jump-to-message (scroll + 2 s highlight flash).
3. **Silent send** — send without triggering notifications via right-click on Send or Alt+click/Alt+Enter; passes `silent=true` in the chat POST body.
4. **Time on hover** — full date/time tooltip when hovering the timestamp, including the edit time if the message was edited.

Items are independent — can be implemented and shipped in any order. Roughly 530 LOC of new code. No new files. No installer growth.

## Section 1 — Presence enhancement

### Data layer: richer status

Currently `ConversationListModel::fetchUserStatuses` stores just the `status` string keyed by userId. The API response also includes `message` and `icon`, which we drop. Fix:

```cpp
// src/models/ConversationListModel.h — private
struct UserStatus {
    QString state;   // "online" | "away" | "dnd" | "offline"
    QString message; // e.g. "in a meeting"; may be empty
    QString icon;    // emoji or short glyph; may be empty
};
QHash<QString, UserStatus> m_userStatuses;

// existing helpers replaced:
QString userStatusForToken(const QString &token) const;        // returns state
QString userStatusMessageForToken(const QString &token) const; // new
QString userStatusIconForToken(const QString &token) const;    // new
```

Parsing in `fetchUserStatuses`:
```cpp
UserStatus u;
u.state   = obj.value("status").toString();
u.message = obj.value("message").toString();
u.icon    = obj.value("icon").toString();
statuses[obj.value("userId").toString()] = u;
```

New roles `UserStatusMessageRole`, `UserStatusIconRole` on the model for sidebar consumption.

### Dedicated poll timer

Add a `QTimer m_statusPoller` to `ConversationListModel`, 60-second interval, single-shot-chained pattern (restart after each `fetchUserStatuses` completes). Start when authenticated; stop on logout. The existing coupling to conversation-list refresh can stay as an additional trigger (cheaper to fire both paths than untangle), but the timer is the primary source.

### Chat header subtitle (1:1 chats)

`HeaderPainter` already draws the conversation title and the typing state. Add a subtitle line under the title for 1:1 conversations:

- If `peerStatusMessage` non-empty → `"{icon} {message}"` (e.g. `"🎯 in a meeting"`; if icon empty, just message).
- Else → localized state: `"Online"` / `"Away"` / `"Do not disturb"` / `"Offline"`.
- Font: 11px, muted color (`m_theme.textMuted`). Typing state (`m_isTyping`) still takes precedence — when typing, show "typing…" instead of the subtitle.

New `HeaderPainter::setPeerStatus(state, message, icon)` supersedes the existing 1-arg version.

### Sidebar dot states

`SidebarPainter::paintRow` around line 362 currently draws a green dot for `status == "online"` on 1:1 rows. Extend:

| State | Dot color | Dot visible? |
|---|---|---|
| online | green (`#5ec76a`) | yes |
| away | amber (`#e0a040`) | yes |
| dnd | red (`#d93025`) | yes |
| offline / empty | — | no |

Keep the 10 px dot geometry. Draw color from a small inline switch.

### Signal plumbing

`SidebarPainter::conversationClicked(token, name, userId, convType, userStatus)` → extend the signal to pass `statusMessage` and `statusIcon` too. `MainWindow::onConversationSelected` already receives `userStatus`; extend its signature. Call `m_header->setPeerStatus(state, message, icon)`.

### Out of scope
- Per-participant status dots on message bubbles in group chats.
- User-facing control to set one's own status. Done via the NC Talk web or mobile clients for now.

Footprint: ~150 LOC across 5 files.

## Section 2 — Message search

### Entry point

New 🔍 magnifier button in `HeaderPainter`'s right-side controls. `HeaderPainter` already has buttons for settings etc.; add the search toggle alongside, emitting a new signal `searchRequested()`. MainWindow responds by showing a search bar widget.

### Search bar widget

A small composite widget managed by `MainWindow` (inline — doesn't need its own file), placed in the chat column above `m_chatPainter`:

- `QLineEdit` with placeholder `"Search in this conversation…"`; autofocus on show.
- ✕ close button on the right.
- 300 ms debounce timer on text changes before firing the API call.
- Results dropdown (`QListWidget` with `Qt::Popup` flag) anchored below the input. Up to 30 results. Each row: bold actor name + relative time on line 1, elided snippet on line 2.

Keyboard: Esc closes the search bar; Up/Down navigate results; Enter picks.

### API

New `ApiClient::searchInConversation(token, query, context, callback)` hitting:
```
GET /ocs/v2.php/search/providers/talk-message-current/search?term=<q>&from=/call/<token>&limit=30
```

`context` is the `QObject *` pattern from v0.17.1 (auto-disconnect on destruction). Callback signature:
```cpp
void(bool ok, const QVector<SearchHit> &hits)
```

Where:
```cpp
struct SearchHit {
    int     messageId;
    qint64  timestamp;
    QString actorName;
    QString snippet;   // server-provided; already HTML-elided around the match
};
```

New header `src/core/SearchHit.h`. Parsing: the Talk unified-search response returns `entries[]` with `attributes.conversation`, `attributes.messageId`, `attributes.timestamp`, `title`, `subline`. Map accordingly.

### Jump-to-message

New `ChatPainter::scrollToMessage(int messageId)`:

1. Search `m_layouts` for that id.
2. **If found**: smooth-scroll via `setScrollY(ml.totalY - height() / 2 + ml.totalHeight / 2)`. Then set `m_highlightMessageId = id` + start a 2-second `QTimer`; while it's active, `paintOwnMessage`/`paintOtherMessage` overlays a fading teal-tinted rect over the bubble (linear easing from alpha 60 down to 0). On timeout, reset `m_highlightMessageId` and `update()`.
3. **If NOT found**: call `m_model->loadHistoryUntil(messageId)` which paginates backward until the id appears (or 5 pages pass). New method on `MessageListModel`. Once loaded, `onRowsInserted` triggers; re-call `scrollToMessage`. If 5 pages pass without finding it, emit `errorOccurred("Message not in loaded history")` and stop.

### Close behavior

Closing the search bar (✕ or Esc) just hides the bar. The scroll position stays wherever the user jumped to. No state cleanup needed beyond clearing the highlight timer.

### Out of scope
- Multi-conversation search. Scoped to the active conv.
- Highlighting the matched term inside the bubble body. The server returns pre-elided snippets in the dropdown — that's enough for location.

Footprint: ~280 LOC.

## Section 3 — Silent send

### Server contract

`POST /ocs/v2.php/apps/spreed/api/v1/chat/{token}` accepts a `silent` boolean body field. When true, the message is stored normally but the server suppresses push notifications to participants.

### Model

Extend `MessageListModel::sendMessage`:
```cpp
void sendMessage(const QString &text, int replyToId = 0, bool silent = false);
```

In the body JSON, add `body["silent"] = true` when the flag is set. All existing call sites pass `silent = false` implicitly (default) — no behavior change.

### Composer UI

- **Right-click on Send button** → context menu:
  - "Send" (default, bold)
  - 🔕 "Send silently — no notification"
- **Alt+click Send** → send silently without opening the menu.
- **Alt+Enter in the composer** → same shortcut.

A transient flag `m_nextSendSilent` on `ComposerWidget` is set before emitting `sendMessage`; reset to false immediately after. `MainWindow` reads it and forwards to `m_messages->sendMessage(text, replyId, silent)`.

New signal from `ComposerWidget`:
```cpp
void sendMessage(const QString &text, bool silent);
```
(The existing `sendMessage(const QString &text)` signal is replaced with this two-arg form; all call sites get `silent=false` by default via the second arg.)

### Feedback

On silent send, briefly flash a 🔕 icon in the Send button's place for 500 ms before reverting. No toast — silent-sending is meant to be frictionless.

### Out of scope
- Per-conversation "default silent" sticky mode. Each message is opt-in silent.

Footprint: ~60 LOC.

## Section 4 — Time on hover

### Approach

ChatPainter is pure QPaint — no child widgets for the timestamp. Use Qt's tooltip event. Override `ChatPainter::event(QEvent*)` to intercept `QEvent::ToolTip`:

```cpp
bool ChatPainter::event(QEvent *e)
{
    if (e->type() == QEvent::ToolTip) {
        auto *he = static_cast<QHelpEvent*>(e);
        QPointF canvas(he->pos().x(), he->pos().y() + m_scrollY);
        for (const auto &ml : m_layouts) {
            if (!ml.timeRect.contains(canvas)) continue;
            QString full = QDateTime::fromSecsSinceEpoch(ml.timestamp)
                              .toString(QStringLiteral("dddd, d MMMM yyyy 'at' HH:mm:ss"));
            if (ml.lastEditTimestamp > 0) {
                QString edited = QDateTime::fromSecsSinceEpoch(ml.lastEditTimestamp)
                                   .toString(QStringLiteral("dddd, d MMMM yyyy 'at' HH:mm"));
                full += QStringLiteral("\nedited ") + edited;
            }
            QToolTip::showText(he->globalPos(), full, this);
            return true;
        }
        QToolTip::hideText();
    }
    return QWidget::event(e);
}
```

### Layout prep

`QRectF timeRect` already exists on `MessageLayout` and is populated in `LayoutEngine::computeLayout` (around line 249). No new layout work needed for this section.

### Edge cases
- System messages and date separators — their full date is already visible; skip the tooltip.
- Messages still `sending`/`failed` — their time slot shows "Sending..." or an error; we still show the tooltip with the best-known timestamp (the local pending timestamp).

### Localisation

Starting format uses `QDateTime::toString(format)`. If a user requests locale-adaptive output, switch to `QLocale::system().toString(dt, QLocale::LongFormat)` in a follow-up.

Footprint: ~40 LOC.

## Verification (manual)

**Presence:**
- 1:1 conversation → header subtitle shows either the peer's custom status (e.g. "🎯 in a meeting") or the localized state ("Online"/"Away"/"DND"/"Offline").
- Set your own away status from another client → TalQ sidebar dot turns amber within ~60 s.
- Set DND → red dot.
- Go offline → dot disappears.
- Typing (other party) → subtitle shows "typing…" instead of status.

**Message search:**
- Click 🔍 in the chat header → search bar appears with focus.
- Type a query → results dropdown shows within 300 ms.
- Click a result → chat scrolls to that message and flashes teal for 2 s.
- Result predates what's loaded → pagination runs (up to 5 pages back), then scrolls/flashes; if not found, error toast.
- Esc closes the bar without resetting scroll position.

**Silent send:**
- Right-click Send → menu shows "Send" + 🔕 "Send silently".
- Click "Send silently" → message sends; other clients receive it but don't get a notification.
- Alt+click Send or Alt+Enter → same, without the menu.
- Normal Send unchanged.

**Time on hover:**
- Hover the time on any message for ~700 ms → tooltip shows full date + time (e.g. "Friday, 18 April 2026 at 14:23:45").
- If the message was edited → tooltip also shows "edited [date]" on a second line.
- Move mouse away → tooltip disappears.
