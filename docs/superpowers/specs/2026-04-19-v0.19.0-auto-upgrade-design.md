# v0.19.0 Design — Auto-upgrade via ncloud.123net.link

Date: 2026-04-19
Status: approved, ready for planning
Author: Kalin (with Claude)

## Summary

TalQ ships installers on a private GitLab that users don't have access to. The update channel instead piggybacks on `ncloud.123net.link` — the Nextcloud instance TalQ already talks to — via a single public-link-with-password folder share. A new `UpdateChecker` polls a small manifest on startup and every 4 hours, shows an in-app banner when a newer version is detected, downloads the branded installer, verifies SHA-256, and launches Inno Setup in silent-upgrade mode so the user's session continues with only a brief relaunch. A "call in progress" guard defers the upgrade until the call ends.

The release script (`scripts/build-release.sh`) is extended to upload installers + regenerate the manifest so future releases auto-publish.

- Endpoints (WebDAV-on-public-share, Basic auth = `<token>:<password>`):

  - Installers: `https://ncloud.123net.link/public.php/webdav/<filename>` where `<filename>` comes from the manifest's `assets` entry.
- Files uploaded: `talq-latest.json` (manifest), `TalQ-v0.18.0-Setup.exe`, `123NET-TalQ-v0.18.0-Setup.exe`.

### Manifest schema

```json
{
  "version": "0.18.0",
  "releaseDate": "2026-04-19",
  "notes": "short plain-text or Markdown release notes",
  "assets": {
    "generic": "TalQ-v0.18.0-Setup.exe",
    "123net":  "123NET-TalQ-v0.18.0-Setup.exe"
  },
  "sha256": {
    "generic": "d9040c66...",
    "123net":  "d4c39633..."
  }
}
```

The client compares `version` against `TALQ_VERSION`, picks the asset filename based on the `TALQ_BRAND_123NET` compile-time flag, and verifies the download against the corresponding `sha256` entry.

## Section 2 — `UpdateChecker` client

New file pair `src/core/UpdateChecker.{h,cpp}`, single class owned by `MainWindow`.

### Public interface

```cpp
class UpdateChecker : public QObject {
    Q_OBJECT
public:
    struct Manifest {
        QString version;
        QString releaseDate;
        QString notes;
        QString assetFilename;   // already brand-picked
        QString assetSha256;     // already brand-picked
    };

    explicit UpdateChecker(QNetworkAccessManager *nam, QObject *parent = nullptr);

    void start();  // begin periodic checks (respects settings opt-out)
    void stop();   // halt

signals:
    void updateAvailable(const Manifest &m);   // fires only when manifest.version > TALQ_VERSION
    void downloadProgress(qreal percent);
    void downloadFailed(const QString &reason);
    void readyToLaunch(const QString &installerPath);

public slots:
    void acceptUpdate();    // triggers download + verify + launch flow
    void deferUpdate();     // hide banner for this session; re-check in 1h
};
```

### Constants (in `src/core/AppSettings.h`)

```cpp
constexpr auto kUpdateManifestUrl = "https://ncloud.123net.link/public.php/webdav/talq-latest.json";
constexpr auto kUpdateAssetBaseUrl = "https://ncloud.123net.link/public.php/webdav/";
constexpr auto kUpdateShareToken = "ezJnLiFtL6K3x4p";
constexpr auto kUpdateSharePassword = "talq-public-updates";
```

### Polling cadence

- Initial fetch: 30-second delay after construction (don't interfere with login flow).
- Periodic: every 4 hours thereafter via `QTimer`.
- "Defer" action: sets a 1-hour override timer; next periodic fire re-evaluates.
- Opt-out: `QSettings` key `updates/autoCheck` (default `true`). When `false`, `start()` is a no-op and any running timer is stopped.

### Fetch + parse

```cpp
void UpdateChecker::fetchManifest()
{
    QNetworkRequest req((QUrl(kUpdateManifestUrl)));
    QString creds = QStringLiteral("%1:%2").arg(kUpdateShareToken, kUpdateSharePassword);
    req.setRawHeader("Authorization", "Basic " + creds.toUtf8().toBase64());
    auto *reply = m_nam->get(req);
    connect(reply, &QNetworkReply::finished, this, [this, reply]() {
        reply->deleteLater();
        if (reply->error() != QNetworkReply::NoError) {
            qWarning() << "UpdateChecker: manifest fetch" << reply->error() << reply->errorString();
            return;
        }
        QJsonDocument doc = QJsonDocument::fromJson(reply->readAll());
        if (!doc.isObject()) return;
        QJsonObject root = doc.object();

        Manifest m;
        m.version     = root.value("version").toString();
        m.releaseDate = root.value("releaseDate").toString();
        m.notes       = root.value("notes").toString();

        QString brandKey = brandKeyForThisBuild();  // "123net" or "generic"
        m.assetFilename = root.value("assets").toObject().value(brandKey).toString();
        m.assetSha256   = root.value("sha256").toObject().value(brandKey).toString();

        if (m.version.isEmpty() || m.assetFilename.isEmpty()) return;
        if (versionNewer(m.version, TALQ_VERSION))
            emit updateAvailable(m);
    });
}
```

Helper `brandKeyForThisBuild()` returns `"123net"` when `TALQ_BRAND_123NET` is defined, else `"generic"`.

Helper `versionNewer(const QString &a, const QString &b)` compares dot-separated numeric components (`0.18.1 > 0.18.0`, `0.19.0 > 0.18.9`). Non-numeric suffixes ignored.

## Section 3 — Download + verify + launch

`UpdateChecker::acceptUpdate()` triggers this flow. Takes the most recently emitted `Manifest`.

### 1. Download

- URL: `kUpdateAssetBaseUrl + manifest.assetFilename`.
- Same Basic-auth header as the manifest fetch.
- Destination: `QStandardPaths::writableLocation(QStandardPaths::TempLocation) + "/talq-update.exe"` (overwrite if exists).
- Stream to disk in chunks via `QNetworkReply::readyRead` → incremental `QFile::write`.
- Emit `downloadProgress(percent)` using `bytesReceived / bytesTotal` from `downloadProgress` signal.
- 10-minute transfer timeout via `QNetworkRequest::setTransferTimeout`.
- On network error or timeout: delete partial file, emit `downloadFailed(QString reason)`.

### 2. Verify SHA-256

- After successful download, read file in 64 KB chunks and feed into a `QCryptographicHash` (SHA-256).
- Compare the hex digest to `manifest.assetSha256` (lowercase compare).
- On mismatch: delete file, emit `downloadFailed("Checksum verification failed")`.

### 3. Launch installer

When call-safe (see guard below), call `QProcess::startDetached` with:

```
<installerPath> /VERYSILENT /SUPPRESSMSGBOXES /CLOSEAPPLICATIONS /RESTARTAPPLICATIONS /NORESTART
```

Flag semantics:
- `/VERYSILENT` — no progress UI.
- `/SUPPRESSMSGBOXES` — Inno's default answers (Yes/OK) for prompts.
- `/CLOSEAPPLICATIONS` — close `talq.exe` cleanly before replacing.
- `/RESTARTAPPLICATIONS` — relaunch `talq.exe` after install completes.
- `/NORESTART` — don't reboot the machine.

Emit `readyToLaunch(installerPath)`. The receiver (`MainWindow`) calls `QApplication::quit()` after a short delay so Qt's teardown completes before the installer overwrites `talq.exe`.

### 4. Call-safe guard

Before launching, `MainWindow` checks:

```cpp
if (m_callManager->callState() != CallManager::Idle || m_callManager->screenSharing()) {
    showToast(tr("You're in a call. Update will start when the call ends."));
    m_pendingInstallerPath = path;
    return;  // re-check on callStateChanged
}
```

A slot on `CallManager::callStateChanged` re-runs the guard when state returns to `Idle` and `m_pendingInstallerPath` is set.

### 5. Failure UX

- Download timeout / network error → toast "Update download failed: {reason}. Retry / Later". Retry re-runs `acceptUpdate`; Later calls `deferUpdate`.
- SHA mismatch → same toast but with message "Update file failed verification". (No auto-retry on the same file — the manifest may need to be re-fetched to get the correct hash.)

## Section 4 — UI: banner + settings

### Update banner

A slim 36 px `QWidget` at the top of the chat column, inside `MainWindow::buildChatPage`. Hidden by default. Shown when `UpdateChecker::updateAvailable` fires.

Layout:
```
[teal 3px accent | ↓ "Update available: v0.18.1"  "What's new" | "Install now"  "Later"  ✕ ]
```

- **Install now** → calls `UpdateChecker::acceptUpdate`. Banner swaps to a progress bar driven by `downloadProgress`. On `readyToLaunch`, banner text becomes "Relaunching to install…" and `QApplication::quit()` fires 500 ms later.
- **Later** → calls `deferUpdate`. Banner hides.
- **✕** → same as Later.
- **What's new** → opens a small modal popover rendering the manifest's `notes` as Markdown via `QTextBrowser::setMarkdown`.

Implementation is inline in `MainWindow.cpp` — no new widget file. One new member `QWidget *m_updateBanner = nullptr;` plus children.

### Settings toggle

`SettingsDialog` gains a new "Updates" section with one checkbox: **"Automatically check for updates"** (default `true`). Key: `updates/autoCheck` in `QSettings`.

On toggle:
- false → `m_updateChecker->stop()`.
- true → `m_updateChecker->start()` (which does an immediate check + schedules the 4-hour timer).

No "Check now" button — the 4-hour cadence plus the startup check is sufficient for TalQ's daily-release tempo.

## Section 5 — Release script auto-upload

Extend `scripts/build-release.sh` to push artifacts + regenerate the manifest after successful builds.

### Environment-driven

Read an app password from env (never committed):

```bash
NC_USER="kalin"
NC_FOLDER="https://ncloud.123net.link/remote.php/dav/files/${NC_USER}/TalQ-updates"

if [ -n "${NC_APP_PASSWORD:-}" ]; then
    echo "[7/7] Uploading to ncloud..."
    GEN_INSTALLER="$SRC_DIR/dist/TalQ-v${VERSION}-Setup.exe"
    BRAND_INSTALLER="$SRC_DIR/dist/123NET-TalQ-v${VERSION}-Setup.exe"
    GEN_SHA=$(sha256sum "$GEN_INSTALLER" | awk '{print $1}')
    BRAND_SHA=$(sha256sum "$BRAND_INSTALLER" | awk '{print $1}')

    # Build manifest — notes from a one-line summary (CHANGELOG head).
    NOTES=$(head -10 "$SRC_DIR/CHANGELOG.md" | tail -9 | head -c 300 | sed 's/"/\\"/g' | tr '\n' ' ')
    cat > /tmp/talq-latest.json <<MANIFEST
{
  "version": "${VERSION}",
  "releaseDate": "$(date +%Y-%m-%d)",
  "notes": "${NOTES}",
  "assets": {
    "generic": "TalQ-v${VERSION}-Setup.exe",
    "123net":  "123NET-TalQ-v${VERSION}-Setup.exe"
  },
  "sha256": {
    "generic": "${GEN_SHA}",
    "123net":  "${BRAND_SHA}"
  }
}
MANIFEST

    curl -sS -u "${NC_USER}:${NC_APP_PASSWORD}" -T "$GEN_INSTALLER"   "${NC_FOLDER}/TalQ-v${VERSION}-Setup.exe" >/dev/null
    curl -sS -u "${NC_USER}:${NC_APP_PASSWORD}" -T "$BRAND_INSTALLER" "${NC_FOLDER}/123NET-TalQ-v${VERSION}-Setup.exe" >/dev/null
    curl -sS -u "${NC_USER}:${NC_APP_PASSWORD}" -T /tmp/talq-latest.json "${NC_FOLDER}/talq-latest.json" >/dev/null
    echo "  uploaded v${VERSION} to ncloud update channel"
else
    echo "[7/7] Skipped ncloud upload (NC_APP_PASSWORD not set)"
fi
```

The guard on `NC_APP_PASSWORD` means local dev builds don't publish. Setting the env var is one-time per machine.

### Old-version cleanup

Older installers stay in the folder — not deleted. Harmless (storage is cheap) and lets you point a specific user at a specific `.exe` URL manually if needed.

## Verification (manual)

- Log into TalQ as a normal user → 30 seconds later, a banner appears if the manifest reports a newer version.
- Click "What's new" → modal shows the notes Markdown rendered.
- Click "Install now" → progress bar fills, then TalQ relaunches in the new version.
- During a call, click "Install now" → toast "You're in a call, will start when the call ends"; end the call → installer launches automatically.
- Toggle off auto-check in Settings → banner never appears until re-enabled.
- Tamper: edit a local copy of the installer, force checker to point at it → SHA mismatch → error toast, no launch.
- Build `scripts/build-release.sh` without `NC_APP_PASSWORD` → build succeeds, upload skipped cleanly.
- Build with `NC_APP_PASSWORD` set → installers + manifest appear in `/TalQ-updates/` folder; manifest points at the new version.
